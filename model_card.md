# Model Card: модель прогнозирования оттока клиентов

## Сведения о модели

- **Разработчик:** Ишбулатова С.С.
- **Дата:** 02.11.2026
- **Версия:** 1.0
- **Тип модели:** бинарная классификация, Random Forest
- **Параметры обучения:** 100 деревьев, `random_state=42`, разбиение 80/20

## Входные данные

- **Формат:** таблица, одна строка - один клиент (CSV или Parquet).
- **Признаки:**
  - числовые: `tenure_months` (стаж), `avg_check` (средний чек), `support_tickets_90d` (обращения в поддержку за 90 дней), `app_logins_30d` (входы в приложение за 30 дней), `purchases_90d` (покупки за 90 дней);
  - категориальные (уже закодированы one-hot): `tariff_plan_basic`, `tariff_plan_standard`, `tariff_plan_premium`, `region_moscow`, `region_spb`, `region_other`.
- **Размерность:** 11 признаков.
- **Предобработка:** пропусков нет (данные синтетические); категориальные признаки закодированы one-hot при генерации.
- **Целевая переменная (только при обучении):** `churn` ∈ {0, 1}, где 1 - клиент ушёл в течение 30 дней после даты среза, 0 - остался.

## Выходные данные

- **Формат:** одно число на клиента - вероятность оттока `p ∈ [0, 1]`.
- **Как читать результат:**
  - `p > 0.7` - высокий риск, клиент идёт в приоритет для звонка отдела удержания;
  - `0.3 ≤ p ≤ 0.7` - средний риск, отправляется автоматическое письмо с предложением;
  - `p < 0.3` - низкий риск, стандартная коммуникация.
- **Порог классификации:** 0.5 по умолчанию. Бизнес может изменить порог, если стоимость ложноположительных и ложноотрицательных срабатываний изменится.
- **Формат выдачи в проде:** JSON вида `{"customer_id": "...", "churn_probability": 0.83, "risk_bucket": "high"}`.

## Назначение и область применения

- **Для чего используется:** прогноз вероятности оттока клиента в ближайшие 30 дней, чтобы приоритизировать работу отдела удержания.
- **Как применяется:** раз в сутки модель прогоняет всех клиентов и выгружает результат в CRM
- **Решаемая задача:** бинарная классификация (target = `churn`: 1 - ушёл в течение 30 дней, 0 - остался).
- **Кто пользуется:** команда маркетинга и клиентского успеха.
- **Где применять нельзя:** решения о кредитовании; клиенты младше 18 лет.

## Факторы

- **Что влияет на качество:** тип тарифа, стаж клиента (tenure), количество обращений в поддержку, средний чек.
- **Что проверяется отдельно:** пол, возраст, регион - используются только для проверки справедливости, не как признаки модели. В текущем синтетическом датасете этих полей нет, проверка справедливости не проводилась.

## Метрики качества

- **Основные метрики:** ROC-AUC, Precision, Recall, F1-score.
- **Порог принятия решения:** вероятность 0.5 (может быть изменён бизнесом).
- **Как проверяли:** стратифицированное разбиение 80/20 с `random_state=42`.

## Данные для оценки

- **Датасет:** синтетические данные, 1000 записей; тестовая выборка - 200 строк (20%).
- **Почему подходит:** данные сгенерированы с целевой переменной, зависящей от признаков, - этого достаточно для демонстрации пайплайна.
- **Предобработка:** пропусков нет; категориальные признаки уже закодированы one-hot.

## Данные для обучения

- **Датасет:** 800 строк (80% от 1000).
- **Предобработка:** StandardScaler не применялся (RandomForest не требует масштабирования); SMOTE не применялся (классы сбалансированы 50/50 по построению).

## Результаты количественного анализа

- **Общий результат:** ROC-AUC = 0.9255 на тестовой выборке (200 строк, `random_state=42`).
- **Как воспроизвести:** `poetry run python scripts/generate_data.py && poetry run python -m churn_model.train`.
- **По группам:** разбивка по возрастным группам и регионам не проводилась - в синтетическом датасете нет этих полей. Для реального проекта требуется отдельный расчёт (целевой разрыв ROC-AUC ≤ 0.05).
- **Комментарий:** высокий ROC-AUC объясняется тем, что целевая переменная в синтетическом датасете детерминированно зависит от признаков. На реальных данных ожидается более скромный результат (0.75-0.85).

## Этические аспекты

- Модель не использует защищённые атрибуты (раса, религия).
- Предсказания носят рекомендательный характер. Финальное решение об удержании принимает человек.

## Ограничения и рекомендации

- **Данные синтетические.** Модель обучена на сгенерированных данных для демонстрации пайплайна; реальные метрики на боевых данных будут отличаться. Перед использованием в проде требуется обучение на исторических данных компании.
- Модель чувствительна к изменению данных. Если тарифная сетка или поведение клиентов заметно поменяются, потребуется переобучение.
- Порог классификации рекомендуется пересматривать ежеквартально - в зависимости от стоимости ложноположительных и ложноотрицательных срабатываний.
